# 报错与异常（需要时再读）

| 脚本输出 | 原因 | 怎么跟用户说 / 怎么做 |
|---|---|---|
| `缺少麦当劳 MCP Token` | 本机没有配置 Token | 去 open.mcd.cn 用手机号登录 → 控制台 → 激活，把 Token 写进 `~/.config/mcd-advisor/.env` 的 `MCD_MCP_TOKEN=`（不要发到聊天里）；在 WorkBuddy 里用的话，也可以在【专家 · 技能 · 连接器】→【连接器】里配好麦当劳 MCP，脚本会直接读取 |
| `Token 无效或已过期`（401） | Token 失效 | 去 open.mcd.cn 控制台重新激活 |
| `请求太快被限流`（429）或「太火爆了，请稍后再试」 | 官方限流（600 次/分钟）或高峰保护 | 脚本已自动等待重试；仍失败就过一会儿再试 |
| `没有收藏门店` | 没给位置，App 里也没收藏门店 | 问用户城市和地标，加 `--city` `--near` |
| `在「…」附近没找到门店` | 地标太偏或写错 | 换一个更常见的地标 |
| `只说了地标，还需要城市` | 缺城市 | 补上 `--city` |
| 退出码 2 + `needsClarification` | 名字有歧义（如「麦乐鸡」有 4 块和 5 块）或菜单里没有 | 把选项原样给用户选，再重跑 |
| 退出码 3，JSON 里 `recommended: null`（文本显示「这次没有拿到任何官方核价结果」） | 门店打烊、不在售卖时段或接口异常 | 说明这次不能给建议；换个时间或换家门店 |
| JSON 里有 `noPlan` | 某样东西只在套餐里卖，而那些套餐会多出别的东西 | 原样转告 `noPlan.onlyInCombos`，建议换规格或换一种东西 |
| `只说了城市，还需要地标` | 缺地标 | 补上 `--near` |
| 文本里「这次有 N 个商品的详情没取到」 | 官方高峰时部分详情查询失败 | 结果仍可用，但可能漏掉个别套餐；过一会儿重跑会自动补取 |
| 某个方案标「官方未能报价」 | 官方核价拒绝了这个组合 | 正常现象，这个方案不参与排名，不用解释细节 |
| `领券必须在终端里亲手确认` | 在非交互环境里加了 `--claim` | 让用户自己在终端运行这条命令 |
